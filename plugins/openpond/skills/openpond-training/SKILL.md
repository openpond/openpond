## Weight-space programming

Use `training_weight_space_capabilities` before preparing an exact source. `training_weight_space_prepare` binds declared local-agent teacher provenance, objective, reviewed development/preservation prompts and explicit duration/idle/work/candidate/output/spend limits; it starts no compute. `training_weight_space_start` requires the user's workload authorization and the returned exact plan/revision/price/spend. Target weights stay remote; the connected local agent controls the loop.

Use `training_weight_space_get` and `training_weight_space_list` for session state. `training_weight_space_command` supports paginated tensor catalog, bounded inspection, typed tensor programs or bounded Python-syntax analysis code, declared-panel evaluation, candidate selection and finalization. It is not an unrestricted Python notebook or general remote shell. Instructions cannot import code, access network/files, run optimizers or perform hidden forwards. Inspect actual tensor geometry before edits; retain the hypothesis and exact candidate. Commands bind the **session revision**; Start/Cancel bind the **execution revision**.

A queued or uncertain command is recovered with `training_weight_space_command_result` using its original session/operation ID. Reuse exact command JSON after uncertain delivery; never mint a fresh ID to replay an edit or evaluation. Failed edits preserve the parent candidate; already consumed work remains charged. Disconnect does not cancel the durable worker. Use `training_weight_space_cancel` and read actual cleanup; source or packaging is not qualified runtime evidence.

Evaluate only declared development/preservation panels during editing. Keep fixed sampling and a baseline. With a declared frozen Dataset release, finalization runs pristine-base and selected-candidate forwards on the same trusted policy-visible inputs. Reserve forward work and wall time for both passes, checkpoint verification, export and transfer. Hosted work duration starts at native-command issuance, so loading and verification consume the approved time; readiness never resets it. Finalize while that headroom remains. Success, failure or interruption closes editing; recover the original operation instead of requesting another finalization. Private answers and graders never enter the worker or editing context.

Use the existing experiment scoring tool for retained WSP outputs: `executionKind: "weight_space"`, exact `execution: {id: sessionId, contentHash: commandResult.contentHash}`, original `weightSpaceOperationId` and explicit `weightSpaceTarget: "candidate"` or `"baseline"`. Baseline is available only from successful sealed finalization. Pin matching Dataset/grader populations and authorized grading spend. Scoring reuses existing budgets/verifiers without another target GPU allocation. A generated answer is not a score. Finalize a nonempty selected patch before `training_weight_space_save_model`. Save pins the exact result/artifact and expected Model revision. Saving does not activate serving. Empty qualification registries must remain unavailable; do not manufacture qualification or claim quality gains.
